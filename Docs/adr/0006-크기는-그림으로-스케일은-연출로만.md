# 크기는 그림으로 — 스케일은 연출로만

[ADR 0001](0001-아트-규격-팀-아트-기준.md) 이 밀도 64 px/unit 을 절대 기준으로 삼으면서, 규격 문구는 "크기는 그림 자체를 키우거나 **스케일로 맞춘다**"고 적었다. 그런데 스프라이트를 1.8배로 늘리면 소스 픽셀 한 칸이 화면에서 1.8배가 된다 — PPU 를 64 에서 35.6 으로 낮춘 것과 화면 결과가 같다. 금지한 수단(PPU 낮추기)과 허용한 수단(스케일)이 같은 일을 하는 구멍이고, 실제로 `MiniBossWolf` 가 PPU 64 를 지키고도 스케일 1.8 로 화면 밀도 35.6 을 만들었다 (#141). 실측 기준 정적 스케일 ≠ 1 인 프리팹이 6개이고, 전부 픽셀아트라 화면 밀도가 64 에서 벗어나 있다.

핵심 관찰: 밀도를 64 로 고정하면 화면 크기는 `픽셀 수 ÷ 64` 유닛으로 접힌다 — **화면에 나올 수 있는 결과는 오직 그림 픽셀 수가 정한다.** 따라서 "PPU 와 스케일의 어떤 조합을 허용하나"는 표현력의 문제가 아니라 표기법의 문제고, 결과가 같다면 표기법은 하나만 남기는 쪽이 기계적으로 검사할 수 있다.

## Considered Options

**스케일 전면 금지 — 런타임 포함.** 가장 단순하지만, 코드가 시간에 따라 흔드는 연출 6곳(`DeathPop`·`GoldCoin` 바운스·`HealthPickup` 펄스·`WalkWobble`·`EscapePortal` 개폐·`SlashEffect` 참격 확대)을 전부 걷어내야 하고, "그 확대는 연출이므로 건드리지 않는다"는 #60 의 결정과 충돌한다. 기각.

**화면 밀도 64 를 규격으로 (`PPU ÷ |lossyScale| = 64`, 수단 자유).** 규격의 '왜'를 그대로 문구화한 형태다. 하지만 위 관찰대로 화면에 나올 수 있는 결과는 채택안과 동일하고, PPU 128 + 스케일 2 같은 표기법만 늘어난다. 판정에 프리팹·씬 계층의 `lossyScale` 계산이 필요해 grep 으로 검사할 수 없고, 상쇄 조합이라는 우회로가 계속 열려 있다. 기각.

그래서 **수단을 하나로 고정**한다: 소스 PPU 64, 프리팹·씬에 저장되는 정적 스케일 (1,1,1). 크기는 언제나 그림 픽셀 수로 맞춘다. 상쇄 조합(PPU 128 + 스케일 0.5 등)도 금지다. 코드가 실행 중에 흔드는 연출 스케일만 허용한다 — 저장소의 런타임 스케일 6곳 중 프리팹에 붙는 5곳은 시작 시 자기 `transform.localScale` 을 읽어 거기에 상대 배율을 곱하는 방식이라(`EscapePortal.cs:35` · `GoldCoin.cs:32` · `HealthPickup.cs:23` · `WalkWobble.cs:29` 는 `baseScale`, `DeathPop.cs:38` 은 `startScale`), 정적 스케일을 1 로 되돌려도 연출은 그대로 동작한다. 나머지 하나인 `SlashEffect.cs:30` 은 프리팹 없이 코드로 생성되며 `transform` 을 읽는 대신 상수(`Vector3.one * 0.85f`)를 대입하므로, 정적 스케일 자체가 존재하지 않아 이 규칙과 무관하다(아래 Consequences). **이 결정으로 바뀌는 코드는 0줄이다.**

## Consequences

- **판정식 한 줄:** 위반 = `spritePixelsToUnits ≠ 64` **또는** 프리팹·씬에 저장된 `m_LocalScale ≠ (1,1,1)`. 각각 grep 한 줄로 검사한다:

  ```
  grep -rL "spritePixelsToUnits: 64" Assets/Art --include="*.png.meta"
  grep -rn "m_LocalScale" Assets --include="*.prefab" --include="*.unity" | grep -v "{x: 1, y: 1, z: 1}"
  ```

  두 번째 커맨드의 히트 중 `.meta` 가 없는 외부 스프라이트를 쓰는 프로토타입(아래 범위 밖 (1))은 규칙 판정 대상이 아니지만, 현재 히트 6건에는 그런 예외가 없다 — 전부 실제 위반이다. 첫 커맨드는 `Assets/Art` 만 훑으므로 월드 픽셀아트를 그 밖에 두면 검사를 빠져나간다 — 새 자산은 [Assets.md](../Assets.md) "반드시 지킬 것" 4항대로 `Assets/Art/<카테고리>/` 아래에 둔다.
- **적용 범위:** 월드에 그려지는 픽셀아트 스프라이트 — 현재 `Assets/Art/` 전부 (방해물 `BigRock`·`BigTomb`·`DeadTree` 의 소스 PNG 포함. 프리팹만 `Resources/Obstacles/` 에 있다). 범위 밖 둘: (1) 저장소에 `.meta` 가 없는 외부 스프라이트(유니티 내장 또는 패키지 제공)를 쓰는 프로토타입 오브젝트 — 임포트 설정이 우리 손에 없어 PPU 를 지정할 수 없다. 현재 씬 1곳(`VillageScene` 의 마을 시설 2개 — #56 이 교체 예정)뿐이다. (2) `Assets/Resources/` 의 화면 공간 UI 이미지(`TitleBg`·`TitleWolf`·`TitleMoon`·`PauseBtn`) — 월드 밀도 개념이 적용되지 않는다.

  이 범위 밖 규정은 **임시 유예이지 영구 면제가 아니다** — 투사체 프리팹 2개가 실증이다. #138 이 내장 원을 `Assets/Art/Projectiles/` 의 PPU 64 스프라이트로 바꾸면서 `Bulllet`·`EnemyBullet` 의 스케일 0.3·0.35 가 1 이 되어, 별도 조치 없이 규칙 안으로 들어왔다 (머지 `ca7960c`).
- **코드 생성 오브젝트의 연출 스케일은 판정 대상 밖이다.** `SlashEffect` 는 프리팹 없이 코드로 생성되고 기본 스케일 상수 0.85 에서 1.45배까지 커진다 — 직렬화된 스케일이 없으므로 판정식에 걸리지 않고, #60 의 "연출은 건드리지 않는다" 결정과 정합한다.
