# 에셋 수집 가이드

> 에셋을 구해오기 전에 이 문서를 읽고, 구해온 뒤에는 맨 아래 "수집 기록"에 추가한다.

## 아트 규격

에셋의 **합격선**이다. 팀이 이미 만들어 저장소에 있는 아트에서 도출했다 — 새로 들어오는 것이 여기에 맞춰야 하며, 그 반대가 아니다. 왜 이렇게 정했는지는 [ADR-0001](adr/0001-아트-규격-팀-아트-기준.md).

- 방향성: **따뜻한 색감의 디테일 있는 픽셀아트** (마을 운영 + 필드 뷰, 레퍼런스 스크린샷 참고)
- **밀도: 64 px/unit — 예외 없음.** 필터는 Point (`filterMode: 0`)
- **정적 스케일: 1 — 크기는 그림으로.** 프리팹·씬에 저장된 스케일은 (1,1,1). 코드가 실행 중에 흔드는 연출 스케일만 허용 ([ADR-0006](adr/0006-크기는-그림으로-스케일은-연출로만.md))
- **타일 한 칸: `PNG 픽셀 ÷ 64` 유닛.** 64px 타일이면 1유닛, 32px 타일이면 0.5유닛
- **캐릭터 세로: 1.1 ~ 1.7 유닛.** 카메라가 `orthographic size: 5`(세로 10유닛)라 화면 높이의 1/6~1/9쯤 된다
- **라이선스: 상업적 사용 가능이 필수.** 크레딧 표기(CC-BY)까지는 허용

### 밀도가 칸 크기보다 먼저인 이유

화면에 보이는 픽셀 한 칸의 크기가 어디서나 같아야 픽셀아트가 한 덩어리로 보인다. 32px 타일 팩을 만났을 때 PPU를 32로 낮추면 한 칸이 1유닛으로 떨어져 편하지만, 그 순간 바닥 픽셀이 캐릭터 픽셀의 2배가 되어 두 레이어가 따로 논다.

**PPU는 언제나 64로 넣고, 칸 크기가 달라지는 쪽을 받아들인다.** Tilemap의 Cell Size를 거기에 맞추면 된다.

| 타일 PNG | PPU | 칸 크기 | 캐릭터가 차지하는 칸 수 |
|---|---|---|---|
| 64×64 | 64 | 1.0 유닛 | 1.1~1.7칸 |
| 32×32 | 64 | 0.5 유닛 | 2.2~3.4칸 |
| 16×16 | 64 | 0.25 유닛 | 4.4~6.8칸 |

## 마을 팩

위 규격을 통과한 **마을 아트가 무엇인지** 적는 절이다. 외부에서 구했든 직접 만들었든, 규격이 기준이고 여기는 그 결과다.

**선정: 외부 팩을 선정하지 않는다 — 마을 아트는 전부 팀 자체 제작이다** (#52).
지형은 #54 가 자체 제작으로 끝냈다. 시설 3채 스프라이트는 #56 이 담당하는데, 그 티켓이
`ready-for-agent` 라 외부 다운로드가 걸리지 않는 경로 — 즉 자체 제작을 전제한다. 다만
#56 본문에 그렇게 명시돼 있지는 않으니, 외부 조달로 뒤집는다면 #56 에서 결정할 일이다.
외부 조달을 전제로 열렸던 "팩 고르기"는 대상이 사라져 종료됐다.

- **지형 타일** (#54): 마을 지형 타일 **28종**, 전부 **64×64 px → 칸 크기 1.0 유닛**.
  `VillageScene` 의 Grid Cell Size `(1, 1)` 이 이 값이다. 임포트는 규격대로 PPU 64 · Point.
  같은 `Assets/Art/Tiles/` 아래 `Hunt/` 에 사냥터 타일 11종이 더 있고 규격은 동일하다 —
  폴더 전체로 세면 39종이므로, 경로로 세지 말고 용도로 셀 것
- 시설: **3채 확정** — 대장간·창고·망루탑 ([GameDesign.md](GameDesign.md) "시설 3채 — 축에 1:1"). 스프라이트는 #56, 망루탑 씬 배치는 #118
- 외부 팩을 고르지 않았으므로 라이선스도 걸려 있지 않다. 시설을 외부 조달로 되돌린다면 위 아트 규격과 함께 **자체 제작한 지형 타일의 색감**에도 맞아야 한다

## 1차 수집 목록 (우선순위)

> 1·2·3 은 팀 자체 제작으로 이미 충족됐다 (아래 "수집 기록 — 팀 자체 제작" 참고).
> 마을 지형 타일도 자체 제작으로 끝났다. 남은 것은 4·5 와 마을 시설이다.

### 1. 플레이어 — 인간 상태
- 탑다운 시점, 4방향(최소 좌우) 이동
- 필요한 애니메이션: **idle(대기) / walk(이동) / attack(공격) / hit(피격) / death(사망)**
- 검색어: `top down character sprite`, `pixel hero 4 direction`, `hunter sprite`

### 2. 플레이어 — 늑대인간 상태
- 인간 상태와 **같은 스타일·같은 크기**여야 함 (제일 어려운 항목)
- 필요한 애니메이션: 인간과 동일 + 가능하면 **변신(transform)** 모션
- 검색어: `werewolf sprite`, `lycan pixel art`, `beast character top down`
- 팁: 같은 작가가 만든 인간+늑대인간이 이상적. 없으면 "인간 팩과 색감·크기가 비슷한 늑대/야수 몬스터"를 늑대인간으로 쓰는 것도 방법

### 3. 일반 적 (2~3종이면 충분)
- 몬스터 여러 종이 든 **팩**으로 구하는 게 효율적 (추후 적 다양화 대비)
- 필요한 애니메이션: idle / walk / death (attack은 있으면 좋음)
- 검색어: `monster pack top down`, `enemy sprite pack`, `undead pack`, `goblin sprite`

### 4. 중간보스
- 일반 적보다 **1.5~2배 크기**, 존재감 있는 실루엣
- 필요한 애니메이션: idle / walk / attack / death
- 검색어: `boss monster sprite`, `elite monster pixel`

### 5. 보스
- 일반 적의 **2~4배 크기**. 150년의 달(슈퍼 블루 블러드문) 보스 후보이기도 함
- 필요한 애니메이션: idle / walk / attack(가능하면 2종) / death
- 검색어: `pixel art boss`, `giant monster sprite`

## 반드시 지킬 것

1. **라이선스 확인** — **상업적 사용이 가능해야 한다.** CC0 와 CC-BY 둘 다 받아들이며, CC-BY 면 크레딧 표기 의무를 아래 표에 남긴다. 비상업 한정 팩은 아무리 예뻐도 보류
2. **출처 기록** — 아래 표에 다운로드 링크 남기기 (나중에 크레딧 쓸 때, 추가 팩 살 때 필요)
3. **밀도 통일** — PPU 는 언제나 **64**, 프리팹·씬에 저장되는 정적 스케일은 언제나 **(1,1,1)**. 화면에서 작아 보인다고 PPU 를 낮추거나 스케일을 키우지 말 것 — 화면 결과가 같은 우회다. PPU 와 스케일을 반대로 틀어 상쇄하는 조합(PPU 128 + 스케일 2 등)도 금지. **크기는 언제나 그림 픽셀 수로 맞춘다** (화면 크기 = 픽셀 수 ÷ 64 유닛). 코드가 실행 중에 흔드는 연출 스케일(팝·바운스·개폐·워블·참격 확대)은 허용 — 근거와 판정식은 [ADR-0006](adr/0006-크기는-그림으로-스케일은-연출로만.md)
4. 파일은 `Assets/Art/<카테고리>/` 아래에 정리 (예: `Assets/Art/Player/`, `Assets/Art/Enemies/`)

## 교정 대상

아트 규격을 위반하는 기존 자산. 규격에 예외를 두는 대신 여기에 적어두고 고친다 — **#60**.

> **판정 기준 (#141 · [ADR-0006](adr/0006-크기는-그림으로-스케일은-연출로만.md)):** 위반 = `Assets/Art/` 스프라이트의 `spritePixelsToUnits` ≠ 64 **또는** 프리팹·씬에 저장된 `m_LocalScale` ≠ (1,1,1). 각각 grep 한 줄로 검사한다 — 커맨드는 ADR-0006 참고. 아래 표는 이 기준 확정 전에 PPU 만 보고 만든 것이라 스케일 위반(`MiniBossWolf` 1.8 등)이 빠져 있다. 새 기준 전면 재계수는 #134.

| 자산 | 현재 PPU | 밀도 | 캐릭터(64) 대비 픽셀 크기 |
|---|---|---|---|
| `HeartOrb` | 16 | 16 px/unit | 4배 |
| `EscapePortal` | 24 | 24 px/unit | 2.7배 |
| `ClawSlash` | 24 | 24 px/unit | 2.7배 |

셋 다 작게 그려놓고 PPU 를 낮춰 화면에서 키운 것이라, PPU 만 64 로 되돌리면 쪼그라든다. 더 큰 픽셀 수로 다시 그려야 한다. 나머지 26개는 규격을 지키고 있다.
